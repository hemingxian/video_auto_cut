## 1. 工作簿结构

| Sheet | 内容 | 机器怎么看 |
|---|---|---|
| 填写说明 | 列说明、上屏标签语法、占位写法、景别/运镜/角度/转场的定义和画面示意、禁止事项、颜色图例、一镜的竖排写法示意 | 刻意避开「一行里有 ≥2 个能被认成列名的格子」，不会被当成第二张表 |
| 项目信息 | 键值行：模板版本 `VAC-SB-1`（程序靠它认模板）、片名、客户/品牌、视频类型、平台、画幅、目标时长、合计时长（公式）、语言、配音音色/语速、BGM、品牌主色/强调色、字体、字幕样式、角标、默认素材范围、禁止出现；另有**转换信息**：原始文件名、SHA-256、转换时间、转换方式、映射档案、转换器版本、核对人、核对完成时间 | 每行只有一个键，不像表头 |
| 分镜脚本 | 表头在第 1 行，列顺序固定；冻结首行和前两列；第 2–200 行预置下拉、文本格式、自动换行；A3 横向打印、每页重复表头 | 唯一一张分镜表 |
| 字典 | 下拉选项来源（放在最后，不隐藏，方便以后增补） | 表头都是不参与识别的词；「卡片提示」这一列故意叫「卡片提示建议」，否则会被认成列名 |

表头颜色：**深蓝 = 软件现在会读，灰色 = 先写着、以后才用**。每个表头都加了批注，写明是否必填以及写法。

## 2. 列定义

「现在是否读取」分三档：**校验**＝既由 qwen-long 解析，又由 `script_card_fields` 按原文逐字校验或当锚点；**解析**＝只进 qwen-long 的 prompt，映射成 plan 字段；**不读**＝目前没有任何地方消费（qwen 最多把它塞进 extra_requirements）。

| # | 列名 | 必填 | 现在是否读取 | 对应 plan 字段 | 以后用途 |
|---|---|---|---|---|---|
| 1 | 镜号 | 必填 | 校验（`shot_no`，分组 + 严格 1..N） | `shot` | 确定性读取器按它排序、分组 |
| 2 | 段落 | 选填 | 不读（qwen 自拟 `module_label`） | `module_label` | 确定性读取时直接当进度条章节名，同名相邻镜合并成一段 |
| 3 | 分镜标题 | 选填 | 校验（`title`，逐字） | `title`（留空时填「分镜N」） | 同左 |
| 4 | 时长(秒) | 必填 | 解析 | `duration`（向上取整成整数秒） | 没有口播的镜按它定时长；有口播的以 TTS 实际时长为准 |
| 5 | 景别 | 选填·下拉 | 不读 | 暂无 | 选材时和素材标签的景别匹配、交给 VLM 评审当约束；新增 `shot_size` |
| 6 | 运镜 | 选填·下拉 | 不读 | 暂无 | 选材时匹配素材的运动类型；静态图或偏短的素材由渲染层做推/拉/摇/移关键帧（ffmpeg zoompan 或 HyperFrames keyframes）；新增 `camera_move` |
| 7 | 拍摄角度 | 选填·下拉 | 不读 | 暂无 | 选材匹配（俯拍/顶拍/平视）；新增 `camera_angle` |
| 8 | 画面内容 | 必填 | 解析（visual） | `visual_query` | 向量检索主查询 + VLM 评审依据 |
| 9 | 口播 | 有配音时必填 | 校验（锚点 `voice_text`） | `voice_text`，同时 `voiceover=true` | 纳入逐字校验，确定性读取直接给 TTS |
| 10 | 字幕 | 选填（留空=同口播） | 校验（锚点 `subtitle`） | `subtitle` | 同上 |
| 11 | 上屏文字 | 选填 | 校验（`card_content` + `card_layout`） | `card_content`、`card_layout` | 同左；以后「参数卡/决策树」各自单做版式 |
| 12 | 卡片提示 | 选填·下拉（可自由写） | 校验（`card_hint`，逐字） | `card_hint` | 以后当包装模板目录里的模板名 |
| 13 | 推荐素材来源 | 选填 | 解析（visual） | 现在进 `clip_requirements` / `production_notes` | `material_bindings`（素材库文件夹 / 指定文件）+ `visual_mode`；「取段」解析成源片时间窗 |
| 14 | 素材要求 | 选填 | 解析（visual） | `clip_requirements` | 选材的硬约束（横竖屏、打码、禁用内容） |
| 15 | 搜索关键词 | 选填 | 解析（visual） | `download_query`（`optimize_queries` 会在它和 `visual_query` 的基础上再改写） | 确定性读取直接当检索词，跳过 `optimize_queries` |
| 16 | 转场 | 选填·下拉（留空=硬切） | 不读 | 暂无 | 新增 `transition`，渲染时做镜间叠化、闪白等 |
| 17 | 备注 | 选填 | 解析 | `extra_requirements` | 同左（音效提示以后单拆出来） |
| 18 | 来源/核对 | 转换件用 | 不读 | 不进 plan | 导入闸门：第一行是「待确认」或「校验失败」的镜，不能正式导入 |

**为什么「音效/音乐」不单独成列**：列数已经顶到识别门槛（见 §3）。整片 BGM 放在「项目信息 › BGM 风格」，逐镜的音效写在备注里（「音效：…」）。等 P0-2 修好再单拆一列。

## 3. 表头为什么这么定（当前代码的硬约束）

`script_card_fields` 进 certain 档的判据和模板的对应关系：

| 判据 | 模板怎么满足 |
|---|---|
| 关键列（镜号 / 口播 / 字幕 / 分镜标题 / 上屏文字 / 卡片提示）必须**白名单原名逐字命中**，不能靠剥括注才认出来 | 六个关键列都用白名单原名；「时长(秒)」要剥括注才认得出，但 duration 不算关键列，所以没问题 |
| 表头行里认出来的列 ÷ 非空列 ≥ **0.6**（`MIN_HEADER_DENSITY`） | 认得出 11 列（镜号、分镜标题、时长(秒)、画面内容、口播、字幕、上屏文字、卡片提示、推荐素材来源、素材要求、搜索关键词），认不出 7 列（段落、景别、运镜、拍摄角度、转场、备注、来源/核对），**11/18 = 0.611**。「推荐素材来源」「素材要求」「搜索关键词」三个名字都是从白名单里挑的，就是为了把比例撑过 0.6 |
| 全工作簿不能有第二行「带上屏/标题列的表头」（`is_field_header_row`：≥2 个格子认得出，且其中有待校验字段） | 填写说明、项目信息都是一行一个键；字典表头改名；plan 字段英文名（如 card_content）一律不写进工作簿，因为它们本身也会被认成列名 |
| 恰好一个 sheet 认得出分镜表 | 示例单独存文件；模板里的空分镜表没有数据行，所以本身不算 |
| 关键列不能有横向合并，也不能有跨镜的纵向合并；选中的 sheet 不能有隐藏行列 | 分镜表不合并、不隐藏（填写说明页有合并，但那一页不参与判定） |
| 表头和第 1 镜之间不能夹内容行 | 表头固定在第 1 行，数据从第 2 行开始 |
| 待校验字段不能落在数值格或公式格上 | 上屏文字、卡片提示、分镜标题等文本列预设成「@ 文本」格式，作者敲「60」也按文本存 |

干跑验证过的余量：再加一列「音效」→ 11/19 = 0.579 → `skipped:table`（这一层完全不工作，比 warn_only 还差一档）。

## 4. 上屏文字写法（与 `LAYOUT_LABELS` / `layout_from_labels` 一致）

- 行首标签只有这几个：`大字：` `副行：` `小字：` `参数卡：` `决策树：`，全角和半角冒号都认。标签不会上屏。不在行首的冒号（如「下一期：」「对接：」）照常上屏。
- 版式对应：大字 + 副行/小字（首行可以不写标签）→ `headline_sub`；每行都是大字，或首行是参数卡/决策树 → `equal_lines`；多行都不写标签、单行、组合拿不准 → 不写 card_layout（渲染层按原规则出，多行时各行一样大）。
- 占位（整格只有它）：`-` `—` `——` `/` `／` `无` `没有` `暂无` `空` `留空` `空白` `不填` `不上屏` `N/A` `（不填）` `（无）`。「没有！」「——（不填）」这类**看着像占位**的写法只会告警、不做处理，填写说明里已经提示作者别这么写。
- 多行：单元格内用 Alt+Enter 换行。不能写 `**` 粗体；标签后面必须带冒号。

## 8. 客户脚本 → 标准模板 转换器（设计）

### 8.1 定位
客户交来的脚本一律**先转成标准模板 xlsx**，由人在 Excel 里核对修改，再由软件做确定性导入。模板本身就是核对页：黄格是待确认的建议，红格是不能导入的错误，「来源/核对」列是逐镜状态。

### 8.2 输入与输出
- **输入**：客户原始脚本（xlsx/csv、docx/md/txt、pdf），可选一份客户映射档案，以及项目默认值（语言、画幅等）。
- **输出**：一份 `VAC-SB-1` 标准模板 xlsx。分镜表填好；项目信息里写好转换信息（原始文件名、SHA-256、转换时间、转换方式、映射档案、转换器版本）；每镜的「来源/核对」写成：

```
待确认                      ← 第一行：已确认 / 待确认 / 校验失败
原文：xxx.xlsx › 分镜脚本 › 第 3 行
AI建议：景别、运镜、拍摄角度、画面内容、搜索关键词
部分摘取：口播 只取了原文 … 的一部分，请确认没漏掉要说的内容
原文含国内/海外两个版本，请删掉本片不用的版本（只能删，不能改字）
```
- **颜色**：AI 建议的格子浅黄 `#FFF2CC`；逐字出处校验失败的格子浅红 `#FFC7CE`；原文搬运的格子不上色。

### 8.3 两条转换路
| 客户脚本 | 怎么转 | 字段来源 |
|---|---|---|
| 表格型（xlsx/csv） | **列映射**：确定性搬运原文。第一次人工（或 AI 提议、人确认）把客户列一一映射到模板列，存成客户映射档案（按客户、按表头指纹复用）；以后同格式的脚本直接套用，全程不调模型 | 映射到的列逐字搬运；映射不到的制作字段（景别、画面内容等）才由 AI 给建议并标黄 |
| 文本型（docx/md/txt/pdf） | **大模型抽取**：按分镜切块，抽出口播、字幕、上屏、标题 | 抽出来的正文必须过逐字出处校验；制作字段是建议，标黄 |

### 8.4 红线与校验规则
1. **口播、字幕、上屏文字、分镜标题只能逐字取自客户原文**，程序做逐字出处校验：
   - 比较时两边都去掉**全部空白和换行**，也都去掉行首版式标签（这是模板语法，不是正文）；
   - 整格必须是**某一段原文**（一个单元格 / md 一格 / 一个段落）里**连续**的一段。所以中间删字、把「／」「｜」换成换行、调换顺序、全角标点改半角都不算通过；
   - 与原文某一格完全相同 = 通过；只是其中连续的一段 = 通过，但标「部分摘取」、状态待确认（用在删掉国内/海外其中一版这种情况）；
   - 找不到 = 这一格标红，这一镜状态写「校验失败」，**不能进入正式导入**。
2. **景别、运镜、拍摄角度、画面内容、搜索关键词、转场、段落**这类制作字段，允许 AI 根据原文画面、取段、图层说明给**建议**，一律标黄、待人确认。AI 不能往四个正文字段里写任何东西。
3. 卡片提示走映射时逐字搬运，AI 不改写；原文没有就留空。
4. 原文里出现多版本标记（国内版/海外版、中文版/英文版）时，照原样搬运，同时标「待确认」，提示人只做删减。

### 8.5 失败处理
| 情况 | 处理 |
|---|---|
| 表头认不出，也没有映射档案 | 进映射向导，由人确认映射（AI 可以提议）；存成档案 |
| 映射档案和表头指纹对不上（客户改了模板） | 不静默套用：列出变化的列，由人重新确认 |
| 文本型切不出分镜 / 模型失败 | 输出只有项目信息的空模板，并报原因；不降级去猜 |
| 出处校验失败 | 格子标红，镜状态写「校验失败」；文件照常输出供人改，导入闸门拒收 |
| 导入时 SHA-256 和手里的原始文件对不上 | 告警：核对的可能不是同一份原文 |
| 仍有「待确认」的镜 | 默认不让正式导入；UI 可以提供「逐镜确认后导入」 |

### 8.6 软件里的入口
「脚本导入」这一步先判断：①标准模板（`模板版本=VAC-SB-1` 且 18 个表头逐字相同）→ 直接确定性导入；②其它表格 → 「转成标准模板」（列映射向导 / 套用已存档案）→ 导出 xlsx，让人用 Excel 打开核对 → 回到软件导入；③文本/文档 → 「AI 抽取成标准模板」→ 同②。这和架构评估阶段 1「脚本导入三分」的做法一致，原来的「整理脚本」一步被这张核对表取代。
