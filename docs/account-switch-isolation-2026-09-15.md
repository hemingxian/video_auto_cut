# 账号切换后的素材隔离修复

状态：已随桌面端 0.5.10 发布，服务端同步部署完成。安装包提取回归和公开下载校验均通过，见 [0.5.10 发布验收](release-0.5.10.md)。桌面端 0.5.9 需要升级后才包含本次修改；视频生成引擎仍沿用 0.5.9。

## 实际原因

“纱桶上下料.mp4”的素材准备失败与脚本解析、视频损坏无关。设备从 A 切到 B 后，共用本地数据库仍保留 A 的文件夹 ID；云端素材下载路径又被普通素材扫描登记为 `cloud/asset/1` 的本地目录。生成前登记采用这条目录链时，提交了属于其他账号的文件夹 ID。

9 月 15 日对应服务端 PostgreSQL 日志实际错误是 `42501 / row-level security policy (USING expression)`。服务端原先捕获全部数据库异常并统一报告“同级文件夹名称已存在”，掩盖了归属问题。

## 修复行为

- 以素材服务地址和稳定用户 ID 建立独立 SQLite，分别保存素材身份、云目录、同步队列、游标、传输状态和任务草稿。令牌刷新不改变数据库；A→B→A 恢复各自记录。
- 旧 `material-library.sqlite` 保留，并制作包含 WAL 数据的一致性隔离快照。无法确认归属的旧云端身份和同步任务不自动分配给当前账号。有效普通本地视频只迁移登记信息，并重新生成身份；不复制或删除视频。
- 排除其他账号的内部云下载缓存，不将它们作为普通本地素材自动扫描、分析或上传。当前账号已下载的云素材仍可使用，保留正确云目录，不重新归入缓存文件夹。
- 账号切换立即失效旧会话，停止后台同步计时器、取消网络传输并停止旧生成进程。迟到响应和旧界面事件被丢弃；必要的收尾仍绑定旧数据库。
- 等待旧下载文件句柄关闭后，才允许新会话操作同一传输文件；不会因旧模型请求长期等待而阻塞新账号云同步。中断同步不消耗重试次数。
- 工作区按账号重建，旧任务队列和素材绑定不继续提交；旧登录、余额刷新和 AI 密钥请求不能覆盖新账号状态。自动备份本地素材的开关按账号保存，新账号默认关闭。
- 服务端仅真实同级名称唯一约束冲突返回 `409 folder_name_conflict`；RLS/权限拒绝返回 `403 folder_access_denied`；其他异常不冒充重名。保留现有账号隔离规则。

## 升级时的数据处理

新账号库首次进入会重新拉取该账号云目录。已下载视频文件保留，可在确认属于当前账号后重新关联。旧库中的账号归属无法可靠还原，因此不迁移旧云同步队列、云目录 ID 或包含这些 ID 的任务草稿；旧库完整保留供后续核对。旧任务若绑定了无法确认归属的目录，需要在当前账号重新选择素材范围。

本次修改不涉及视频生成引擎的转码、分析缓存算法，也不代表已修复此前单独讨论的 Qwen 分析结果导出空记录问题。
