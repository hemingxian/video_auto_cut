## 0. 一句话

客户的脚本不一定是我们的 Excel 模板，很多会是让 AI 写的文字稿。**0.5.16 让软件对「什么格式的脚本」都一视同仁**：同一套标准字段，Excel 和 Markdown 两种写法都能直接精确导入；不按标准写的脚本由 AI 整理成同一套字段，但整理出来的每一项都标「待确认」，人在编辑抽屉里点过才算数；整篇就是口播稿的，可以勾「口播稿」让原文逐字当口播；编辑抽屉只剩一种版面。

## 2. 现状摸底（a29d74f，读代码得出）

### 2.1 导入入口与分流

桌面端只认文件扩展名，选完脚本就交给引擎：`electron/file-extensions.ts` `SCRIPT_EXTENSIONS = .xlsx .xlsm .xls .docx .doc .pdf .txt .md .csv .json .srt`。引擎 `main.rs:402-409`：`--script-file` 走 `script.rs:73-108` `read_plan_from_script_ai`，起内置 Python 跑 `tools/normalize_script.py`。**分流全在 Python 里**（`normalize_script.py:388-468`）：

| 输入 | 怎么走 | 有没有模型 | 证据 |
|---|---|---|---|
| **xlsx/xlsm 且是 VAC-SB-1 模板**（「项目信息」有 `模板版本=VAC-SB-1` + 「分镜脚本」18 列表头逐字对上） | `script_template.detect` → `import_template`，确定性逐列映射 + 导入闸门（红格/正文黄格/镜号/时长等阻断） | **零模型** | `normalize_script.py:403-424`；`script_template.py:92-118`（识别）、`:159-414`（映射与闸门） |
| xlsx 有 `VAC-SB-N` 标记但版本或表头不对 | 阻断，不退回 AI | 零 | `script_template.py:102-117` |
| **其它一切**：非模板 xlsx/xlsm/xls、md、txt、docx、doc、pdf、csv、json、srt | 整个文件上传 DashScope → qwen-long 解析（`prompts/script_parse.md`）→ 口播字幕缺失时再复核一轮（`script_parse_review.md`）→ `compact_plan` → `script_card_fields.verify_and_fix` 按原文纠正上屏/卡片提示/标题 → Qwen 复核章节标签 | **有**（解析 1 次 + 复核 0~1 次 + 章节标签 0~2 轮） | `normalize_script.py:425-468`；纠正器只认 `card_content/card_hint/title` 三个字段（`script_card_fields.py:97`），md/txt 按「分镜 N + 键：值」切块（`:112-129`、`:654-735`），xlsx 按表头角色（`:200-243`）；pdf/doc/xls 纠正器零动作（`:106-108`） |

结论：**md 现在一律走 AI**；用户 9/30 现场看到「.md 脚本走普通字段、没有原文/景别」就是这个原因。docx/pdf 也只能走 AI。

### 2.4 「待确认」机制现状

- **只有模板路有**。来源两处：xlsx 单元格底色（黄 `FFF2CC` / 红 `FFC7CE`，`script_template.py:39`、`:204-225`）和「来源/核对」列第一行（`:226-241`）。
- 正文（标题/口播/字幕/上屏）和时长黄格 → **阻断导入**（`CRITICAL_FILL_COLUMNS`，`:32-33`）；制作字段黄格 → 可导入，字段名进 `review.ai_suggested`。
- 抽屉：`ai_suggested` 里没被 `confirmed` 的算待确认；`warnings` 里没被 `acknowledged` 的算提醒（`shotPlan.ts:337-354`）。改了制作字段 = 自动确认（`withConfirmedField`，`:194-203`、`:209-223`、`:129-135`）；**改正文字段不会自动确认**（`updateShotContent` 对 title/voice/subtitle/card 不调它，`:108-127`）——模板路正文黄格本来进不来，所以以前不需要。
- 确认只写 shots.json，不回写 Excel；重新导入就重置。
- 非模板路：没有 `script_meta`，没有任何待确认。

### 2.5 AI 现在会「自己写」的东西（G2 要管住的）

`prompts/script_parse.md`：
- 口播：脚本有逐字口播就照抄；脚本**要求配音但没给正文**时，允许 AI 按文档内容**生成**口播（规则 6、第 7 行）。
- 字幕：允许 AI 压缩口播或**生成**一句字幕（规则 8）。
- 标题、章节名：允许改写（规则 3）。
- 画面描述 / 搜索词：AI 写（规则 4、5）。
- 上屏/卡片提示：必须逐字照搬，没写留空（规则 14、15），并有程序纠正兜底。
- 景别/运镜：提示词里**没有**这两个字段，现在 AI 不输出。

## 3. 标准字段规范 v1（草案）

**原则**：字段名、含义、空值规则全部沿用 VAC-SB-1（`模板设计说明.md` §2、9/23 方案 §3.3），**一个字段不改名**；新增只有两处（§3.3），都是为了「AI 整理」这条新路。规范版本号仍叫 **VAC-SB-1**（同一套字段，换载体不换版本）。

### 3.1 分镜字段（每镜 18 项）

「来源」三档：**脚本** = 只能照抄脚本原文；**AI** = 非标准脚本时 AI 可以整理/归纳（标待确认）；**系统** = 程序算出来的。标准载体（Excel/Markdown）里所有字段都只取作者写的。

| # | 字段名（Excel 列 / Markdown 键） | 存到哪 | 必填 | 取值 | 空值语义 | 非标准脚本来源 | 上屏？ | 校验 |
|---|---|---|---|---|---|---|---|---|
| 1 | 镜号 | `shot`；`script_meta.source` 记位置 | 必填 | 整数，1..N 连续 | — | 系统（按 AI 切分顺序编号） | 否 | 标准载体：不连续/重复/空 → 阻断 |
| 2 | 段落 | `module_label` + `script_meta.segment` | 选填 | 短章节名 | 空 = 程序按既有规则兜底 | AI（优先用脚本已有的小标题，必要时缩短） | **是**（进度条章节名） | 语言检查换掉时提醒 `module_label_replaced` |
| 3 | 分镜标题 | `title` | 选填 | 文本 | 空 = 「分镜N」 | 脚本有标题列/小标题就照抄；没有则 AI 起短名 | 间接（段落为空时进度条用它） | 标准载体黄格阻断；非标准由纠正器按原文纠正 |
| 4 | 时长(秒) | `duration`（向上取整），非整数原值存 `script_meta.duration_raw` | **标准载体必填** | 正数 | — | 脚本写了照抄；没写 AI 估，标待确认 | 否 | 标准载体空/非数/≤0 → 阻断；有口播的镜最终以配音实长为准 |
| 5 | 景别 | `script_meta.shot_size` | 选填 | 字典 9 项 | **空 = 「不限」** | **只抄脚本明写的；没写填「不限」，不推断** | 否 | 不在字典 → 提醒 `not_in_dictionary`；非标准见 §6.3 核对 |
| 6 | 运镜 | `script_meta.camera_move` | 选填 | 字典 16 项 | 空 = 「不限」 | 同上 | 否 | 同上 |

### 3.2 占位与空值（三种载体共用，沿用现有函数，不新写一套）

- 占位写法：`-` `—` `——` `/` `／` `无` `没有` `暂无` `空` `留空` `空白` `不填` `不上屏` `N/A` `（不填）` `（无）` → 当空（`script_card_fields.is_placeholder`）。
- 「像占位」的（「没有！」「——（不填）」）→ 不改写，只提醒 `doubtful_value`（`field_doubt`）。
- 景别/运镜/拍摄角度：空、占位、「不限」三者含义相同。存储上：**AI 整理路显式写「不限」**；标准载体（Excel/Markdown）作者留空就不写键，保持 0.5.15 的 xlsx 输出逐字节不变。界面上空和「不限」显示一样（见 §7）。

### 3.3 新增的两处（及理由）

| 新增 | 位置 | 取值 | 理由 |
|---|---|---|---|
| `script_source.route` 新值 `"organized"`；Markdown 标准载体**仍用** `"template"`，另加 `script_source.carrier = "markdown"`（xlsx 不写这个键） | plan 顶层 | `template` / `organized` | md 和 xlsx 是同一规范，用同一个 route，渲染层（`render_segment.py:138`）和桌面端（`shotPlan.ts:162`）对 md 零改动；xlsx 不写 `carrier`，0.5.15 的 xlsx 输出能保持逐字节不变。`organized` 区分「AI 整理」，界面据此显示「AI 整理 · 全部待确认」 |
| `script_meta.field_origin` | 每镜 | `{字段名: "script" \| "ai" \| "default" \| "system"}` | 用户要看到每个字段是脚本原文、AI 整理还是默认「不限」；只在 `organized` 路写（标准载体全是 script，不写，保持 xlsx 逐字节不变） |

其余全部复用：待确认字段仍放 `review.ai_suggested`（界面已按它计数和显示黄条），确认仍放 `review.confirmed`，提醒仍放 `review.warnings`/`acknowledged`，导入快照仍放 `script_values`（「人已改/恢复原文」照旧可用；`organized` 路的「原文」= AI 整理结果）。`schema_version` 仍是 2。

## 4. Markdown 载体格式（草案）

### 4.1 语法（给程序的确定性规则）

1. 文件扩展名 `.md` 或 `.txt`；UTF-8（带不带 BOM 都行）或 GB18030；CRLF/LF 都行。
2. **识别标记**：有一个二级标题 `## 项目信息`，其下有一行 `- 模板版本：VAC-SB-1`。没有这行 = 不是标准 Markdown，走 AI 整理路（与 xlsx 规则一致）；有标记但版本不对、或结构错 → **阻断**，不退回 AI。
3. 第一个一级标题 `# …` 是片名的展示用（可省；以「项目信息 › 片名」为准）。第一个 `## ` 之前的其它内容（说明文字）一律忽略。
4. 每镜一个二级标题：`## 分镜 N`（N 从 1 连续递增）。标题行后面可以跟「｜标题」，但**只做展示**，分镜标题以「- 分镜标题：」为准。
5. 镜内每个字段一行：`- 字段名：值`。字段名必须是 §3.1 的 17 个名字之一（镜号由标题给出，不写「- 镜号」）；全角/半角冒号都认；字段名两边的 `**` 粗体自动去掉（AI 爱加粗）。允许的别名只有一个：`时长（秒）` = `时长(秒)`。
6. **多行值**（上屏文字、来源/核对常用）：冒号后留空，下面每行缩进 2 个空格（或 1 个 Tab）；遇到下一个不缩进的 `- `、下一个 `##` 或空行结束。缩进去掉后逐行保留，行内空白不动。
7. 不写的字段 = 该格为空；一个 `## 分镜 N` 小节里所有字段都为空 = 空行，跳过（与 xlsx 预置空行一致，所以空白模板导入结果 = `no_shots` 阻断）；同一镜同一字段写两次 → 阻断；不认识的字段名 → 进 `extra_columns` + 提醒（同 xlsx 自加列）。
8. 代码围栏 ``` 里的内容一律忽略。
9. **待确认标记**（Markdown 没有底色，用「来源/核对」代替颜色）：
   - 第一行 `校验失败` → 阻断（= 红格）；
   - 有一行 `AI建议：景别、运镜、画面内容`（顿号/逗号分隔字段名）→ 这些字段进 `ai_suggested`（= 黄格）；**其中出现分镜标题/口播/字幕/上屏文字/时长 → 阻断**（= 正文黄格，与 xlsx 同一规则）；
   - 第一行 `待确认` → 提醒；其余说明行 → 提醒 `status_note`。
10. 导入闸门、提醒码、事件格式、`script_meta` 形状**全部与 xlsx 模板相同**；单元格坐标换成行号（`cell` 写「第 23 行」）。

### 4.2 与 xlsx 一一映射

| xlsx | Markdown |
|---|---|
| 「项目信息」sheet 每行 A 列键 / B 列值 | `## 项目信息` 下 `- 键：值` |
| 「分镜脚本」第 1 行 18 个表头 | 字段名（镜号由 `## 分镜 N` 给出） |
| 第 n+1 行 = 第 n 镜 | `## 分镜 n` 小节 |
| 单元格内 Alt+Enter 换行 | 冒号后换行 + 缩进续行 |
| 黄底 | 「来源/核对」里的 `AI建议：…` 行 |
| 红底 | 「来源/核对」第一行 `校验失败` |
| 第 19 列起作者自加列 | 不认识的字段名 |
| 「填写说明」「字典」sheet | 不需要（字典在程序里，与 xlsx 同一份常量） |

**等价要求**：同内容的 xlsx 和 md 导入后的 plan，除 `script_source.file_name / file_sha256 / carrier` 和每镜 `script_meta.source`（sheet+row ↔ carrier+line）外，**深相等**（含 `script_meta.review`、`script_values`、`card_layout`、`render_hints`、`module_label`）。另外两处已知差异不算不等：①提醒/阻断条目里的 `cell`（`R2` ↔ `第 N 行`）；②**xlsx 的 `project_info` 现在会多出一个 `"项目": "填写"`**（`script_template._info` 把「项目信息」sheet 的表头行也当成了键值，`a29d74f` 实测），md 里没有这行。②是 xlsx 导入器的小毛病，本轮**不修**（修了会破坏 N1 逐字节），比较时剔除这个键即可。

## 6. 非标准脚本 AI 整理规则

### 6.1 走哪条路

`normalize_script.main()` 分流顺序：①VAC-SB-1 xlsx（不变）→ ②**VAC-SB-1 Markdown（新增，确定性）**→ ③其余一律 **AI 整理路**（`route="organized"`）。③就是现在的 Qwen 路改造而来：上传 → qwen-long 解析 → （口播缺失时）复核 → `compact_plan` → 纠正器 → 章节标签，**模型调用次数和种类不增加**；新增的只是提示词多要几个字段 + 一段确定性的后处理（§6.2–6.4）。

### 6.2 字段分三类

| 类别 | 字段 | AI 能做什么 |
|---|---|---|
| **只能照抄（正文）** | 上屏文字、卡片提示、字幕、推荐素材来源 | 只能逐字取原文，原文没有就留空。上屏/卡片提示/标题沿用现有纠正器按原文纠正（`verify_card_fields`，不放宽）；AI 给的字幕若在原文里找不到（去空白后不是原文连续片段）→ 清空（=同口播）+ 提醒 `subtitle_not_in_script` |
| **口播（单列）** | 口播 | 脚本有逐字口播 → 照抄，来源 `script`；脚本要求配音但没给正文 → AI 可代写，来源 `ai`，属正文、必须确认才能生成；**口播稿模式** → 只能是原文正文的逐字切片，来源 `script`（§6.7） |
| **只提取明写、不推断** | 景别、运镜、拍摄角度、转场 | 只有脚本里明明白白写了才填；没写：景别/运镜/拍摄角度填「不限」，转场留空（=硬切）。程序复核见 §6.3 |
| **可以整理（制作）** | 段落、分镜标题（脚本没有时）、时长（脚本没写时）、画面内容、搜索关键词、素材要求、备注、项目信息里明写的项 | AI 可以归纳、缩写、从口播推出画面描述；全部标待确认，来源记 `ai` |

### 6.3 「不推断」的程序复核（不靠 AI 自觉）

1. 提示词要求 AI 对景别/运镜/拍摄角度/转场每个非空值同时返回 `evidence`（原文摘录）。
2. 程序核对：①值在字典里；②`evidence` 去空白后是原文的连续片段；③`evidence` 里含这个字典词。三条都满足才保留，来源记 `script`；否则改成「不限」（转场改空），提醒 `camera_inferred_dropped`，原 AI 值写进提醒正文。
3. 「原文」怎么拿：md/txt/csv/json/srt 读文本（复用 `script_card_fields.read_script_text`），xlsx/xlsm 读全部单元格文本（复用 `script_tabular`），**docx 新增一个纯标准库读取**（zip 里 `word/document.xml` 的段落文字）。pdf/doc/xls 读不了 → 这四项**一律**填「不限」/空，提醒一条 `camera_unverifiable`。
4. 字典别名不做（写「近景特写」不算「特写」）；拿不准一律「不限」——宁可少填，不可瞎填。
5. **单字值（推、拉、跟、升、降、甩）另加一条**：`evidence` 里还必须出现「镜头」或「机位」，否则按推断处理改回「不限」。原因：这几个字在普通口播里很常见（步骤 0 的散文样例第 3 镜口播「节拍才**跟**得上产线」就含「跟」），只靠「含这个字」挡不住 AI 硬凑。

### 6.4 「待确认」的存储

`organized` 路每镜 `script_meta`（与模板同形，界面不用新读法）：

```jsonc
"script_meta": {
  "v": 1,
  "source": { "route": "organized", "file": "原文件名", "evidence": "AI 给的本镜原文位置/摘录，可选" },
  "segment": "…", "visual_description": "…", "shot_size": "不限", "camera_move": "推", "camera_angle": "不限",
  "material_source": "…", "material_requirements": "…", "search_keywords": "…", "notes": "…",
  "authored": { "card_content": "纠正后的上屏原文（带标签）" },          // 有上屏时
  "script_values": { "title": …, "voice_text": …, "subtitle": …, "card_content": …, "card_layout": …,
                     "card_hint": …, "visual_description": …, "shot_size": …, "camera_move": …,
                     "camera_angle": …, "transition": … },               // 导入快照（=整理结果），「恢复原文」回到这里
  "field_origin": { "title": "ai", "voice_text": "script", "shot_size": "default", "camera_move": "script", … },
  "review": {
    "status": "待确认",
    "status_lines": ["待确认", "AI 整理自：xxx.md"],
    "ai_suggested": [ /* 本镜所有标准字段，含正文和「不限」项 —— 用户要求「全部标待确认」 */ ],
    "confirmed": [], "warnings": [ … ], "acknowledged": []
  }
}
```

plan 顶层 `script_source = {"v":1, "route":"organized", "format":"VAC-SB-1", "file_name", "file_sha256", "project_info":{只放明写项}, "dictionaries": 同模板, "import_summary"}`。

- 「全部标待确认」= 每镜 `ai_suggested` 列出该镜**所有**标准字段（为空的字段也列，确认的是「这里确实不需要」）。字段名用 `script_meta`/plan 里的键名（`title、voice_text、subtitle、card_content、card_hint、module_label、duration、visual_description、shot_size、camera_move、camera_angle、transition、search_keywords、material_requirements、material_source、notes`）。
- `render_hints.caption_source` 规则与模板相同（字幕非空且≠口播才写）；渲染层把生效条件从 `route=="template"` 扩成 `route in {"template","organized"}`（`render_segment.py:138`），`incremental.rs:160` 的注释同步改。

### 6.5 确认与清除

- **确认** = 字段名加进 `review.confirmed`（现有机制）。**改了就算确认**：现在只有制作字段改了会自动确认，要补上正文字段（标题/口播/字幕/上屏/版式）——只对 `ai_suggested` 里有它的镜生效，模板路正文本来不在 `ai_suggested`，行为不变。
- 每镜「本镜全部确认」保留；**不加全片一键确认**（§9 已定 1）。
- 一镜 `ai_suggested` 全部确认、`warnings` 全部「知道了」→ 头部状态由「● 待确认」变「已确认」（**派生显示**，不改写 `review.status` 原值，便于审计）。
- 「恢复原文」对 `organized` 路回到整理结果（`script_values`），按钮文字改成「恢复整理结果」。
- **生成闸门（§9 已定 1）**：任一镜的正文字段（`title / voice_text / subtitle / card_content`，含 `card_layout`）在 `ai_suggested` 里且未确认 → 「生成」被拦，提示「还有 N 镜正文未确认：第 x、y 镜」，并可一键跳到第一处。确认方式只有两种：点该镜「本镜全部确认」，或改过该字段一次。制作字段未确认只在生成前弹一次提醒，不拦。模板/标准 Markdown 路正文不会出现在 `ai_suggested`，不受影响。
- 确认只写 shots.json（+ SQLite 草稿），重新导入就重新整理、重新待确认（与模板一致，提示里写明）。

### 6.6 禁止推断 / 禁止生成清单（测试逐条锁）

| 字段 | 规则 |
|---|---|
| 景别、运镜、拍摄角度 | 没明写 → 「不限」；有值必须过 §6.3 三条核对 |
| 转场 | 没明写 → 空（硬切）；同上核对 |
| 上屏文字、卡片提示 | 原文没有 → 空；有则逐字（纠正器兜底） |
| 字幕 | 原文没有 → 空（=同口播）；AI 压缩/生成的一律清空 |
| 推荐素材来源 | 原文没有 → 空；AI 不编路径、不编取段时间 |
| 口播 | 有原文照抄；要求配音但没给正文时 AI 可代写（来源 `ai`，必须确认）；口播稿模式下只能是原文切片（§6.7） |
| 项目信息 | 只放原文明写项；画幅/语言等没写不填 |

### 6.7 口播稿模式（用户 10/08 新增）

**给谁用**：有人把整份脚本写成一篇口播稿（就是要念的话），不想 AI 改一个字。

**入口与默认**（界面见 §7.5）：工作台选完脚本文件后，脚本行下面一个勾选框「这份脚本就是口播稿（原文逐字当口播）」，**默认不勾**，每个任务单独选，不记忆。只对 `.txt / .md / .docx` 可勾（其它格式置灰，悬停说明「这种格式读不出确定的原文，不能用口播稿模式」）。

**与标准载体的关系**：只在非标准路（AI 整理）生效。勾了但文件其实是标准 Excel/Markdown（有 `模板版本：VAC-SB-1`）→ **忽略这个选项**，按标准导入，提醒一条 `voice_script_ignored`「标准脚本已有口播列，已忽略口播稿选项」。不阻断。

**正文确认（导入前预览）**：勾上后点「预览分镜」，先弹「确认口播正文」窗：
- 原文按段落列出，每段前一个勾选框，勾 = 算口播正文。默认不勾：`#` 开头的标题行、`## 项目信息` 整节、形如「标题：/片名：/作者：/时长：」的短键值行（键 ≤6 字）、代码围栏、空行；其余默认勾上。用户可以随意改勾。
- 底部显示：已选正文字数、按 4.2 字/秒估算时长。
- 点「确认并导入」→ 把勾选段落按原顺序、以换行连接，写成 UTF-8 文件 `<数据目录>/temp/voice_script_body_<任务id>.txt`，随任务传给引擎；点「取消」不导入。
- 原文读取：txt/md 按 UTF-8（带不带 BOM）→ GB18030 依次尝试；docx 取 `word/document.xml` 的段落文字（表格单元格内段落也算，各成一段）。读取放在桌面端主进程还是调 Python 由 Codex 先查现有能力再定（回帖说明）；**无论哪边读，引擎只认这份确认后的正文文件**，不再自己从原文件抽，避免两边读法不一致。

**怎么传到引擎**：任务参数新增 `voiceScriptBodyPath` → 引擎命令行 `--voice-script-body <文件>` → `script.rs:73-108` 原样转给 `normalize_script.py --voice-script-body`。这要改 Rust，**和 S5/S6 合在同一次重编**。队列项要存这个路径，续跑/重新预览时沿用；文件丢了 → 报错「口播正文文件已不存在，请重新选择脚本」，不静默退回普通模式。

**切镜怎么做（推荐，保证不可能多字少字）**：
1. 不上传原文件，把确认后的正文直接放进提示词，要求 AI 输出分镜，但每镜**不返回口播全文**，只返回 `voice_start`：本镜口播在正文里开头的 8–20 个字，逐字照抄；其余字段（段落、标题、画面内容、搜索关键词、素材要求、时长、景别等）照 §6.2–6.3 规则。
2. 程序把正文做「去全部空白」归一（含全角空格、换行、Tab），同时记下归一前后位置对照；按顺序在正文里找每镜的 `voice_start`（同样去空白）：第 1 镜必须从正文开头开始；每个起点必须在上一个之后、唯一可定位（从上一个起点往后找第一处）；找不到 / 顺序倒了 / 第 1 镜不在开头 → **阻断**。
3. 每镜口播 = 原文从本镜起点到下一镜起点之间的那一段（取**原文**片段，只去首尾空白、内部换行折成一个空格，与现有 `voice_text` 口径一致）。
4. **最终校验（用户要求，独立于第 2–3 步）**：各镜 `voice_text` 按顺序拼接、去全部空白后，必须与正文去全部空白后**逐字相等**；标点、全半角、数字写法都不放宽。不等 → 阻断，报告第一处不一致的位置（第几镜、期望/实际各前后 20 字）。
5. 阻断时：不写输出、`VACUT_EVENT` 失败事件（复用 `scriptImport.blocked`，`code` 用 `voice_script_mismatch` / `voice_start_not_found` / `voice_start_out_of_order`），队列面板显示原因，**不自动重试**（重试 = 再点一次导入，算新的一次模型调用）。

**结果数据**：`script_source.voice_mode = "verbatim"`、`script_source.voice_body_sha256`（确认后正文文件的哈希）；每镜 `script_meta.source.voice_span = [起, 止]`（归一后正文里的位置）；`field_origin.voice_text = "script"`。字幕一律留空（= 跟口播）；上屏文字仍只取原文明写（口播稿里一般没有，则全空）。

**待确认口径**：口播来源是脚本、已逐字校验，**不进 `ai_suggested`**，不受生成闸门拦；但切镜位置是 AI 定的，信息条加一句「口播按原文逐字切分，分段位置由 AI 决定，请检查每镜起止」。其它字段（标题、画面、段落、时长等）照常全部待确认；**标题仍是正文字段，未确认照样拦生成**。导入后人在抽屉里改口播 = 人已改（不再做全文校验）。

**不做**：口播稿模式下 AI 不改写、不删口头禅、不补字；不支持「部分是口播、部分是说明」的自动区分（靠预览窗人工勾）。

## 7. 编辑抽屉统一版面

### 7.1 总原则

- **只有一个组件**：所有镜头都用同一套全字段版面（把现在的 `TemplateShotFields` 扩成通用版，删掉 `ShotEditorDrawer.tsx:326-333` 的老分支）。
- 字段有没有值、能不能恢复、是不是待确认，全靠数据决定，**不看是哪条路导进来的**；只有顶部信息条文字按 route 不同。

### 7.2 排布（从上到下）

1. **顶部信息条**：
   - 模板（xlsx/md）：「标准脚本 VAC-SB-1（Excel / Markdown）· 片名 · N 镜 · 待确认 N 条 · [只看待确认]」
   - AI 整理：「AI 整理 · 原文件名 · N 镜 · 待确认 N 条（正文未确认不能生成）· [只看待确认]」
   - 旧任务：「旧任务（0.5.16 前生成）· 部分字段无原始信息」
2. **镜头头部**：序号 · 分镜标题 · 段落 · 时长 · `!N` · 状态（● 待确认 / 已确认）。
3. **第一组「观众听到和看到的」**（正文）：分镜标题 → 口播 → 字幕（灰字「留空 = 同口播」）→ 上屏文字（上：原文只读小字；下：内容文本框 + 版式下拉）→ 卡片提示（只读）。
4. **第二组「画面和素材」**：画面内容 → 景别 / 运镜 / 拍摄角度 / 转场（一行四个下拉；空和「不限」都显示「不限」，转场空显示「硬切（默认）」）→ 搜索关键词 → 素材要求。（现有「素材搜索词」「剪辑要求」改名为与模板一致的「搜索关键词」「素材要求」，数据键不变。）
5. **每个字段的小标签**：来源（`脚本` / `AI 整理` / `默认`，取 `field_origin`；模板路一律不显示，避免满屏「脚本」）+ 待确认黄竖条 +「确认」+「人已改 / 恢复…」。
6. **「更多」折叠区**（只读）：段落、时长、推荐素材来源、备注、来源/核对、自加列、项目信息。
7. **提醒列表**：逐条 + 「知道了」；底部「本镜全部确认」。
8. **素材绑定区**：现有组件，不改。

### 7.3 编辑规则

沿用 0.5.15 已验收的写回逻辑（`shotPlan.ts:108-135`、`:177-223`、`:311-335`）：改字幕同步 `render_hints`、上屏少于 2 行自动删版式、改画面内容同步 `visual_query` 并重置自动选材、改四个下拉不重置选材。新增：§6.5 的「改正文即确认」。

### 7.4 旧任务（没有 `script_meta` 的 shots.json）

- 同一版面；正文和画面字段照常可看可改（读写现有 plan 键：`title/voice_text/subtitle/card_content/card_layout/visual_query/download_query/clip_requirements`）。**这意味着旧任务第一次能看到和改 AI 解析出的上屏文字**。

### 7.5 工作台：口播稿入口与正文预览（§6.7）

- 工作台「脚本文件」行下面加勾选框「这份脚本就是口播稿（原文逐字当口播）」，默认不勾；文件格式不是 txt/md/docx 时置灰并给悬停说明。换文件时勾选自动清掉。

## 9. 风险与用户拍板

### 9.1 风险

| 风险 | 缓解 |
|---|---|
| 抽取 xlsx 逐镜构造给 md 复用时改动了 xlsx 输出 | N1 逐字节对照，每步都跑 |
| AI 整理路改提示词后，真实模型输出与以前不同（口播/标题措辞变） | O1 只能证明「后处理不改旧字段」；真实输出靠步骤 6 散文 E2E 人看。改提示词只加字段、不改原有规则句（Mac 逐句审） |
| 景别等「明写」核对过严，客户写「近景特写」被判不限 | 有意为之（宁少勿错）；提醒里带原 AI 值，人一眼能补选 |
| 旧任务也开始显示上屏文字，用户可能发现以前看不到的 AI 臆造卡片 | 这是好事；旧任务编辑不加 `script_meta`，不影响续跑 |
| route 新值 `organized` 让 `render_hints` 生效，而 `route` 不在缓存键里 | 只在新导入的 plan 出现；旧 plan 无 `render_hints`，哈希不变（N2） |
| 桌面版本与运行包混装（新桌面 + 旧引擎/旧 tools） | 旧 tools 不产出 `organized`，抽屉按旧任务显示，不崩；验收一律新 tools |
| 小项 S5/S6 + 口播稿参数转发需重编引擎 | 集中一个提交、只编一次、回帖锁 SHA |
| 口播稿模式下 AI 给的起点定位到正文里重复出现的句子 | 按顺序从上一起点往后找第一处；最终拼接校验兜底，错了就阻断（V6） |
| 口播稿正文里夹着标题/说明没被剔除，会被念出来 | 导入前预览窗人工确认；默认规则剔除标题行、项目信息节、短键值行 |
| 生成闸门变硬后，用户觉得 AI 整理脚本「点不动」 | 提示里写清还差哪几镜、可一键跳转；改过一次即算确认 |

### 9.2 用户拍板（2026-10-08，六条全部已定，无待定项）

1. **已定：AI 整理的脚本，正文（标题/口播/字幕/上屏）没确认不能生成。** 确认方式：点该镜「本镜全部确认」，或改过一次；不设全片一键确认。制作字段（景别、画面等）没确认只提醒、不拦。模板和标准 Markdown 不受影响。（§6.5、步骤 4）
2. **已定：脚本要求配音但没给正文时，AI 可以代写口播**，来源标「AI 整理」，必须人确认；**字幕不再由 AI 生成**，脚本没写就留空 = 跟口播走。**另新增「口播稿模式」**：导入时可勾「这份脚本就是口播稿（原文逐字当口播）」，默认关；勾上后原文正文逐字当口播，AI 只切镜和填其它字段；程序校验各镜口播按顺序拼起来 = 原文正文（只允许空白/换行差异），不符就阻断；这时口播算「脚本明写」，不算 AI 整理；只在非标准路生效，标准 Excel/Markdown 忽略此选项；导入前弹窗让用户确认哪些段落算正文。（G5、§6.7、§7.5、步骤 3b）
3. **已定：转场没写 = 留空 = 硬切；景别/运镜/拍摄角度没写 = 「不限」。** 转场字典不加「不限」。
4. **已定：本轮做「AI 写脚本提示词」，线下发文件**：提示词（§5）+ 空白模板（Excel `分镜脚本模板_v1.xlsx` 与 Markdown `分镜脚本模板_v1.md`）+ 示例（`示例_食品码垛_v1.xlsx` / `.md`），由 Mac 在步骤 0 入库。软件内「下载模板」入口放到下一轮。
5. **已定：Markdown 标准载体也接受 `.txt`**，识别靠文件里的「模板版本：VAC-SB-1」标记，不靠扩展名；没有标记的 txt 照旧走 AI 整理。
6. **已定：小项并入** S3 纯文本标题纠正、S4 被拦时提示像成功、S5「AI 解析失败」误导、S6「分镜数: 6」、S7 重启后打开文件夹报未登记、S2 字幕拆词 + 换行处保留空格；**S1 卡片标题拆词本轮不并入**（留给 0.5.17）。

### 9.3 其它已定口径

- AI 整理结果不导出成标准文件，只在软件里确认。
