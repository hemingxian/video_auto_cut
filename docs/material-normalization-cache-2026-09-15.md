# 跨分镜、跨任务标准化缓存

本轮修复同一批素材因分镜路径不同而被重复转码的问题。共享位置为 `<data_root>/video/normalization-cache/v1/<原素材 SHA256>/<标准化参数摘要>/`。缓存参数包括协议版本、FFmpeg 文件摘要、完整转换参数以及实际生效的编码器；硬件失败回退 CPU 时，以 CPU 参数记录结果。

每个分镜仍有自己的 `_indexed_h264`，通过硬链接或复制取得共享结果，搜索范围保持独立。复用前验证源文件、缓存输出的内容摘要和大小，并用 ffprobe 验证 H.264、30fps、有效尺寸/时长及 AAC 音频格式。已有文件超过 1024 字节不再作为有效依据。OS 文件锁避免相同内容并行重复编码；临时文件完成校验后才发布，不覆盖其他分镜可能持有的旧文件 inode。

输出旁的 `<视频名>.source.json` 使用 `schema_version:1`，包含 `source_path`、`source_sha256`、`source_size`、`normalized_sha256`、`normalized_size`、`normalization_profile` 和 `time_mapping:"identity"`，供分析缓存验证原始内容身份。路径本身不是复用凭据。

当前索引目录内不属于本轮输入的旧投影及 sidecar 移到同级 `_indexed_h264_stale`；该目录同时从原素材扫描中排除。移动前校验两个目录的真实绝对路径都属于当前素材工作目录，保留原素材与共享缓存。

## 隔离验证

- 生成并实际转码三份不同尺寸、24fps、44.1kHz 的短视频：第一镜标准化 3 次，第二镜不同路径/文件名标准化 0 次，新任务标准化 0 次。
- 两个并发镜头竞争相同内容，仅实际标准化 1 次。
- 缓存改成无效字节，即使同步伪造其大小和内容摘要，也被媒体格式校验拒绝并重建。
- 原素材内容改变、质量参数改变正确失效；实际 CPU 回退结果按 CPU 参数复用；编码中源文件变化则拒绝发布。
- 旧目录中大于 1024 字节的无效投影被校验后的共享结果替换；失败转码不产生可用投影或来源证明。
- 旧投影归档测试通过：不进入当前搜索目录、不重新成为原素材候选、不修改原素材。
- 缓存 3 项（含显式执行的 2 项真实 FFmpeg 测试）、归档 1 项以及原逐镜续跑 6 项测试通过。

测试只使用系统临时目录中的自建短视频，无真实账号、模型调用或用户素材/数据库操作。真实全链路与安装包验证由主任务继续执行。
