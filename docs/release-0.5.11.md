# 0.5.11 启动黑屏修复

状态：2026-09-15 已发布。正式与 RC 更新清单均为 0.5.11，公开安装程序与已验收候选的完整文件校验通过。

## 原因与修复

0.5.10 新增的账号会话保护直接使用 `Proxy` 包裹 Electron `contextBridge` 暴露的 API。真实桥接对象被冻结，其 `taskStatus` 等方法是不可配置的只读属性；代理返回包装方法违反 JavaScript 属性约束。用户登录后工作台首次读取 `api.taskStatus`，同步抛出 `TypeError`，React 根节点被清空，形成有标题栏但界面纯黑的现象。

此前普通 JavaScript 对象单测和安装包内后端模块测试不具备真实 Electron 桥接冻结行为，因此遗漏了这一发布缺陷。

修复改为独立的代理对象，把原始桥接对象保留为方法调用对象。继续阻止旧账号工作区调用及迟到响应，不修改或解除 Electron 桥接的冻结保护。

## 验证

- 使用 0.5.10 安装包 ASAR 中未经修改的生产界面和真实 `preload.cjs`，在隐藏 Electron 窗口中复现精确错误：`taskStatus` 的只读不可配置属性代理异常、页面文字为空、根节点子元素为 0。
- 修复后的生产界面在相同真实桥接条件下，已有登录账号 A 启动、实际点击界面退出登录、未登录页启动、已有登录账号 B 启动通过，任务状态 IPC 正常发出，页面根节点存在，无界面异常。
- 冻结/不可配置 API 回归 4 项通过，覆盖原调用对象、注销后拒绝调用、迟到响应和同步取消订阅。
- 桌面全量测试 356 项：354 通过、2 项原有跳过、0 失败。
- 发布流程新增必过步骤：打包后从 ASAR 加载真实预加载与生产界面做隐藏窗口启动验收，失败则打包流程失败。
- 从最终 NSIS 安装包重新提取 ASAR，108 个编译文件与构建一致；提取模块 154 项回归通过。使用该提取 ASAR 再跑真实 Electron：账号 A、未登录、账号 B 三个启动场景均无控制台错误，工作台可见且无阻塞弹窗；离屏渲染截图已人工核对。期间窗口始终隐藏。

窗口测试使用隔离资料目录、模拟业务 IPC 返回值且阻断 HTTP/HTTPS；没有使用真实用户凭证、安装到用户目录、操作鼠标键盘或进行实际素材生成。它验证真实 Electron 运行时与界面的启动集成，不替代云服务业务端到端测试。

## 版本与升级

仅桌面端更新为 0.5.11，服务端保持已部署的账号隔离错误分类版本，引擎保持 0.5.9。本次黑屏发生在界面初始化，不是素材文件损坏或云端数据删除。

覆盖安装修复包即可，无需卸载或清空数据。账号隔离升级时的数据处理规则沿用 [0.5.10 发布说明](release-0.5.10.md)。
